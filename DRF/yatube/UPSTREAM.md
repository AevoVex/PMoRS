# Исходные тесты и Postman-коллекция

Источник: [yandex-praktikum/api_yatube](https://github.com/yandex-praktikum/api_yatube/tree/723eec8d3618349e42980d2d69b52605f00128f2), commit `723eec8d3618349e42980d2d69b52605f00128f2`.

Через GitHub получены файлы `tests/` и `postman_collection/`. Все 13 файлов побайтно соответствуют исходнику; ожидаемые Git blob-хеши сохранены в [upstream-manifest.json](upstream-manifest.json). Проверки в тестах и коллекции не переписаны под реализацию.

Локальный `pytest.ini` адаптирован к существующей структуре проекта и современному pytest: `pythonpath = .`, `DJANGO_SETTINGS_MODULE = yatube_api.settings`. Штатный `tests/conftest.py` ожидает `yatube_api/manage.py`; этот совместимый вход вызывает основной `manage.py`, не копируя приложение или данные.

Модель Comment соответствует полям исходной модели; вместо замены всей базы добавлена миграция к уже существующим Post и Group. Прямого сброса базы и повторного клонирования поверх работающего проекта не было.

## Запуск тестов

Из папки `yatube`, используя Python своего окружения:

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest
```

## Запуск коллекции

Из папки `DRF`:

```powershell
..\.venv-drf\Scripts\python.exe scripts\run_postman.py
```

Нужен установленный Postman CLI. В этой сессии использована версия 1.80.0. Скрипт создаёт временную БД и учётные записи, предусмотренные оригинальной коллекцией; рабочую базу не меняет. Во временной копии JSON заменяется фиксированный порт 8000 на свободный порт, тестовые скрипты не изменяются. CLI получает `--no-report-events` и `--no-insecure-file-read`.

Оригинальный `postman_collection/set_up_data.sh` содержит `flush` и очищает выбранную базу. Он сохранён как часть исходных материалов и **не запускался**. Для текущего проекта используйте описанный выше изолированный запуск. Для ручного исследования можно импортировать JSON в Postman, но ему нужна отдельная подготовленная база и пользователи из исходного README; демо alice/bob не заменяют эти учётные записи.
